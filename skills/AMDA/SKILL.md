# AppMagic市场分析

将固定的AppMagic周度数据表更新为固定的“AppMagic市场分析”飞书文档。分析全球市场和国家群组，不写周报；除US外，不以单一国家作为主线。

## 固定资源

- 每次调用首先读取并校验本地私有资源配置：默认路径由`scripts/verify-local-resource-config.ps1`解析到本机应用数据私有目录；如设置了`AM_MARKET_ANALYTICS_CONFIG`，则使用该环境变量指定的路径。
- 配置必须提供`data_workbook.url`和`formal_document.url`。前者是唯一的数据工作簿，读取其中全部日期命名且可见的周度工作表；后者是确认后的正式覆盖目标。
- 资源地址只允许保存在上述本地私有配置中，仅在运行时用于直接读取资源和生成原生表格链接对象；不得写入Skill正文、引用文件、日志、报告正文、提交或远程仓库。
- 配置缺失、字段缺失或地址无效时必须停止，不得搜索云文档、要求用户重新指定资源或自行补全地址。
- 常规更新必须先生成独立草稿文档。Demo文档首段固定写为“基于AppMagic数据的全量历史周度数据整理，供审校确认。确认前不会覆盖正式市场分析文档。”其中“AppMagic数据”必须使用配置中`data_workbook.url`对应的原生表格链接对象，不得改成纯文本、普通超链接或其他文档链接；正式文档首段只保留数据来源说明，不得带Demo审校提示。

## 隐私约束

- 固定资源地址、Wiki节点标识、账号标识、访问令牌、机器绝对路径和本地配置内容只保存在本机私有配置中，不得写入Skill、引用文件、示例、日志、报告正文、提交或远程仓库。
- 日志和验收反馈只输出校验状态、文件数量和提交范围，不输出实际资源地址、资源标识或配置内容。
- 发现历史文件、生成物或待提交内容出现上述信息时，先停止发布并完成清理；不得以当前工作区已清理代替历史和远程版本检查。

## 新建文档位置

- 涉及新建文档（包括更新草稿）时，如用户没有明确指定其他位置，严禁放入飞书云盘或任何文件夹；只能创建在“我的文档库”根目录。
- 使用 `lark-cli docs +create` 时，必须显式传入 `--parent-position my_library`。仅在用户明确指定目标文件夹、知识库或其他位置时，才可改用相应的 `--parent-token`。

## 本地产物目录

- AMDA 图表分析产生的所有本地产物（五张 SVG/PNG、`.render-stages/` 中间文件、数据 JSON 等）一律写入 AMDA 项目文件夹内的 `output\charts\` 子目录；项目文件夹由环境变量 `AMDA_PROJECT_DIR` 指定，未设置时默认使用 AMTools 仓库内的 `skills\AMDA` 目录。
- 禁止把上述产物写入 Codex 工作仓库根目录、`output/`、`artifacts/`、`diagrams/`、`tmp/` 或任何其它位置。
- 调用 `scripts/render-market-charts.ps1` 或 `scripts/render-category-countries-chart.ps1` 时，不传输出参数时脚本默认输出到该目录；显式传参也只能指向 AMDA 项目文件夹内部。

## 必须先读

1. 读取`references/report-contract.md`、`references/analysis-framework.md`和`references/examples.md`。规则文件与示例文件必须成对读取，不能只读取规则而跳过示例。
2. 执行`scripts/verify-local-resource-config.ps1`并读取本地私有资源配置，再直接读取配置绑定的AppMagic数据工作簿和固定目标文档；写入前不得使用未读取的资料。
3. 使用`lark-sheets`读取固定工作簿；仅在需要本地临时副本进行透视、聚合或公式核验时使用`spreadsheets`，不得写回来源工作簿。按`references/analysis-framework.md`进行分析推理，使用`lark-doc`创建和写入草稿文档，编辑已有画板时使用`lark-whiteboard`。
4. 固定结构的市场分析更新不等待大纲确认，但开始分析前必须先向用户确认本次分析截止日期以及纳入或排除的周度工作表；即使用户已在请求中给出日期，也要先用一句话回显确认，确认前不得开始日期范围分析。日期确认后，再使用`doc-coauthoring`的结构与读者验收方法生成具体观点内容；只有准备替换正式文档时才向用户请求确认。其他整篇写作或重构仍按`doc-coauthoring`提交大纲和材料清单并等待确认，局部修改只改指定区块。
5. 每次更新必须先在“我的文档库”根目录创建一个新的demo文档；完成数据、图表、表格、API回读和可见渲染核验后，把demo交给用户确认。用户确认前绝不能直接修改正式文档，也不得执行正式文档的替换或删除。仅在用户明确授权覆盖后更新正式文档；覆盖完成后必须重新回读正式文档，并通过数据、数值、结构、图表、表格、正式版一致性和可见渲染验收，且当前批次没有`ERROR`、`FAIL`或failed工具调用，才删除本批次demo。任一验收失败、未确认或状态不一致时必须保留demo，不得提前删除。AMDC定时批次遵循下方“定时任务特殊规则”的已授权自动覆盖例外，不再等待逐批人工确认。

## 定时任务特殊规则

- 只有AMDC的Windows定时采集批次完成且同步成功后，才能触发AMDA；手动采集、手动同步和其他来源的运行不得触发AMDA。
- 每个定时批次只创建一个Demo文档。文档标题固定为`AM-Demo-yyyymmdd`，其中日期取本次定时运行日期；创建后立即把URL写入批次注册文件，当前批次的读取、写入、回读、可见检查和重试始终使用该URL，不搜索、不解析其他Demo、不创建第二个Demo。
- 定时路径是通用日期确认规则的明确例外：读取固定工作簿内全部日期命名且可见的周度工作表，排除隐藏表、非日期表和非周度表；不得等待手动日期确认，也不得自行补造工作表。
- 定时路径在Demo生成和写前验收阶段将正式市场分析文档作为只读基线；Demo及全部写前校验通过后，由触发器调用确定性的正式发布器，使用同一批次和同一注册URL对正式正文做局部block替换、原位更新五张已有画板，并保留正式标题和资源token。正式版回读、数据/数值/结构/图表/表格/一致性及五张画板预览全部通过后，自动删除本批次Demo；任一环节失败都保留Demo并从失败阶段恢复。通知由触发器统一发送到`appmagic`主题，只发送最终成功或失败通知，并保留AMDA阶段耗时。
- 定时导出新来源快照前，先保留上一份`all-sheets-csv.json`，再运行`scripts/verify-source-drift.py`比较重叠历史工作表的记录数和内容；新周表属于正常新增，历史记录数或内容变化只输出不可阻断的WARN，不得静默覆盖。
- 定时分析必须调用`scripts/analyze-amda.py`作为唯一原始数据计算入口，再调用`scripts/prepare-report-data.py`生成图表数据；禁止在`output\\charts`内临时生成或改写第二套分析脚本。国家份额必须按每条“应用×周”记录先归一化后跨有效记录等权聚合。
- 定时写入前后必须运行`scripts/verify-report-numeric-parity.py`，逐项核对分析JSON、图表数值标签和Demo五张表格，数值不一致时不得写入或输出成功标记。

## Demo与正式版一致性

- Demo必须复用正式版的章节顺序、标题层级、画板位置、说明块样式、表格结构和列表层级。第二节趋势表后保留正式版要求的空段落；总结内层列表数量固定为`4/4/3/2/3`。
- 五张表均为总宽`820px`，正文行数依次为`4/3/7/7/7`。各列按当前表头和正文内容测量后分配宽度：表头、品类、分组、数值和百分比等短内容必须单行显示，说明列保留最低可读宽度并承接剩余空间；没有说明列时，在满足单行容量后将剩余宽度均匀分配给各列。表头和正文单元格必须显式设置垂直居中，水平对齐按整列换行状态确定。
- 分品类决策表的“IAP观察层”只能来自收入侧分组；“近期信号”单元格必须按“下载侧分组、收入侧观察分组、收入数据覆盖率”三段式表达，使用两个显式换行，不得改写成单纯的最近4周下载趋势。
- 表头使用正式版的`rgb(242,243,245)`背景；分析说明块使用浅蓝`rgb(240,244,255)`与边框`rgb(130,167,252)`，结论说明块使用浅绿`rgb(240,251,239)`与边框`rgb(142,224,133)`。图表只能使用批准版SVG模板，不得重新设计坐标、字体、间距或图表类型。
- 写入前保存正式文档和Demo的API回读，运行`scripts/verify-formal-parity.ps1`；写入Demo后保存全文API回读，再次运行该校验，并同时通过数据、图表、表格、报告契约和文档结构校验，以及五张画板的可见渲染检查。定时批次正式发布时，Demo首段的审校提示不得复制到正式文档；正式发布后必须使用`scripts/verify-amda-document.ps1 -FormalDocument`重新回读正式文档，拒绝全文流程话术并重复全部检查。任何一项失败都不得输出成功标记`AMDA_AUTOMATION_FINAL_OK`或发送成功通知。

## 已确认规则与示例

执行报告写作、重构或局部修订时，逐条对照以下规则和`references/examples.md`。每条采用的规则后必须紧跟一个可见示例；示例只说明结构和表达方式，示例中的数字不能替代当前工作簿数据。

0.**日期确认：**开始AppMagic市场分析前，先向用户确认截止日期以及纳入或排除的周度工作表；确认前不得开始日期范围分析。合成示例：`开始分析前先确认：本次是否截至2030年2月25日，纳入2030年2月25日周表？`
1.**数据范围：**按用户明确的起止日期取数，包含最早有效周，不纳入用户排除的周。合成示例：`数据范围为2030年1月7日至2030年2月25日，不纳入2030年3月4日数据`
2.**IAA与IAP口径：**下载侧只用于判断IAA用户规模和潜在广告库存偏好，收入侧只用于判断IAP收入偏好。示例：`下载侧T2+T3用于判断IAA规模，收入侧美国与T1用于判断IAP验证优先级`
3.**国家名称：**正文、表格和国家诊断使用完整国家或地区名称，US、T1、T2和T3只保留为分组标签。示例：`印度、印度尼西亚和巴基斯坦是T3的重点国家`
4.**组内国家诊断：**每个重点分组继续拆到具体国家，说明国家构成、集中度和近期变化来源，不能只写分组名称。合成示例：`Launcher下载侧T2+T3为72.0%，其中印度、巴西和印度尼西亚合计52.0%`
5.**综合总结：**总结按整体数据特征、发展趋势、IAA品类分组和国家重心、IAP重点及收入覆盖率限制组织为有序列表分点，使用飞书原生有序列表，需要细分时内层嵌套自动字母，只描述市场结构，不写执行规则。示例：`总结章节用有序列表分成5条，第1条写整体数据特征、第2条写发展趋势、第3条写IAA品类分组和国家重心、第4条写IAP重点、第5条写收入覆盖率限制，细分内容内层自动显示为a.`
6.**公式位置：**公式只在“数据范围与口径”章节说明一次，使用行内LaTeX，不单独成行，也不在其他章节重复。示例：`归一化份额写在第二章句内，公式前后均有中文说明`
7.**变量说明：**公式出现的每个英文字母、英文缩写和英文单词都在公式说明处解释。示例：`a. i (index)：一条“应用×周”记录`
8.**括号形式：**括号内外均为英文时使用半角括号，括号内含中文时使用全角括号。示例：`i (index)`和`收入侧（income side）`
9.**嵌套列表：**使用飞书原生嵌套有序列表，外层显示数字、内层自动显示字母，不手写圆点加字母，也不使用`type="a"`。示例：`外层3.下嵌套<ol><li seq="auto">，浏览器显示为a.`
10.**表头与列宽：**表头和标题列不得出现不必要的换行，标题过长时先调整列宽。示例：`收入数据覆盖率｜全历史｜前4周｜最近4周｜近期变化｜近期特征`保持表头单行显示
11.**表格对齐：**表头和单元格垂直居中；同一正文列只要没有单元格需要自动换行就整列水平居中，主动使用`<br/>`拆行且每一行都能在列宽内单行显示时不算自动换行，仍可居中；只要存在会触发自动换行的单元格，整列左对齐。示例：`分组角色与国家诊断`使用主动换行且每行均可单行显示时，该列正文也居中；内容会触发自动分行时才整列左对齐
12.**表格标点：**表格内不使用句号，出现分号直接改为换行并删除分号。合成示例：`下载侧72.0%<br/>收入侧US+T1 48.0%`
13.**趋势横轴：**趋势图横坐标使用实际日期，覆盖批准的数据范围，不使用第几周替代日期。合成示例：`2030-01-07、2030-01-14、2030-01-21……2030-02-25`
14.**元素间距：**不同元素之间保留足够距离，组合元素以整体边界计算中心，文字、分界线、图例和标签不得重合。示例：`图例组以整体边界居中，相邻图例项至少保留72px间距`
15.**写入验收：**写入后必须API回读并进行浏览器可见检查，不能只依据接口成功返回。示例：`回读确认公式只在第二章，浏览器确认表头未换行且图例和分界线没有重合`
16.**局部更新：**更新已有文档（demo或正式）时，只替换需要替换的内容：行内文本用`str_replace`，整块内容用`block_replace`/`block_insert_after`/`block_delete`，禁止用`overwrite`整篇清空重写；未变更的画板、图片、表格等资源块必须保留原token。示例：`只替换“近期信号”表格的某一格文字时用block_replace定位该格，其余表格和画板保持不变`
17.**标题保留：**覆盖正式文档时只覆盖正文，不覆盖标题；正式文档必须保留原标题（如“AppMagic市场分析”），demo标题（如“AppMagic市场分析Demo20300225”）只用于demo文档。合成示例：`demo标题为AppMagic市场分析Demo20300225，覆盖正式文档时保留“AppMagic市场分析”，不写入Demo后缀；若误带demo标题，只用drive files patch改回正式标题，正文不动`
18.**数据支撑：**每条结论必须带具体数据支撑，写明指标名称、数值和对应周期；证据不足时只保留方向性观察或待验证动作，不写无数据的判断。合成示例：`下载侧T3首周38.0%、末周44.0%；Launcher下载侧前三个重点国家合计52.0%`

## 工作流

0. 开始分析前，先向用户确认本次分析截止日期以及纳入或排除的周度工作表；确认前不读取日期范围数据、不统计指标、不生成观点。
1. 读取本地配置绑定的工作簿中全部日期命名且可见的周度工作表，并读取配置绑定的正式文档结构和样式。先在“我的文档库”根目录创建新的demo文档完成更新，不得直接覆盖固定目标文档。国家群组必须使用固定名单，不得自行增删、改名或重分层。
2. 统计“应用×周”记录、下载国和收入国的可用记录、Top5份额、缺失率、国家代码和按品类拆分的收入数据覆盖率；本次更新严格按用户确认的日期范围执行，不自行沿用历史日期或纳入被排除的周表。
   - 原始计算统一使用`scripts/analyze-amda.py`，不得在运行时重写等价逻辑；`scripts/prepare-report-data.py`只负责把分析结果转换为渲染器和Demo共用的数据结构。
3. 按`US`、`T1`、`T2`、`T3`顺序互斥归组；拉美、东南亚、IN是可重叠补充组。马来西亚归T3，美属萨摩亚仅保留一次。
   - IAP观察层按收入侧全历史分组份额从高到低排序；前两组合计达到50%时使用两组，否则使用第一组；收入覆盖率低于50%时追加“方向性”标识，表格、正文和图表必须共用该结果。
4. 下载国Top5仅代表IAA用户规模与潜在广告库存偏好；收入国Top5仅代表IAP收入偏好。两项口径各说明一次。
5. 先执行分析框架：完成数据质量台账、趋势判断、异常归因假设、洞察和行动建议，并保存每条结论对应的指标证据；每条结论必须带具体数据支撑（指标、数值、对应周期），证据不足时只保留方向性观察或待验证动作。对每个重点分组继续列出具体国家、国家份额集中度、全周期与最近4周变化和变化来源；证据不足时只保留方向性观察或待验证动作。
6. 使用`doc-coauthoring`按固定结构组织数据、图表、分析和结论，并写入新的demo文档；不等待大纲确认，先生成具体观点，结论必须由本品类或群组数据支撑。总结章节用有序列表分点收束全文，依次列出整体特征、趋势、IAA品类及国家重心、IAP重点和覆盖率限制，需要细分时内层嵌套自动字母，只描述市场结构，不写执行规则，不把同一结论拆散成重复短句。
7. 在数据、口径和结论均已锁定后使用`deslop`检查分析文案。只删除空泛、重复或模板化表达，不得改动数字、固定术语、判断类型或行动建议。

## 格式硬约束

- 使用平铺直叙、简明中文，按数据、解释、行动结论的顺序表达。

- 图表使用深色柱形或堆叠柱形；柱内文字使用24px常规字重并水平、垂直居中；图例色块和文字整体居中。
