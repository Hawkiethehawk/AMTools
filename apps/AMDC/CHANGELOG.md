# Changelog

所有重要变更都会记录在此文件中。

仅在用户明确要求推送时，才为该次发布更新本文件和项目版本号；没有推送指令的本地修改不递增版本号，也不新增版本记录。

## [1.1.8] - 2026-08-10

### 变更

- 新增定时 AMDC 完成后的 AMDA 自动触发：仅来源为 `scheduled` 且采集、Excel 生成和飞书同步全部成功时触发；手动采集、补采和手动飞书同步不会触发。
- 自动收尾等待全部历史记录完成落盘，并在短暂写入竞态时重试，避免同步或 AMDA 更新被过早跳过；同一 AMDC 批次通过批次 ID 去重。
- 固化 AMDA Demo 触发边界：每个定时批次只创建一个 `AM-Demo-yyyymmdd` Demo，后续读取、写入、回读和重试固定使用同一地址；正式市场分析文档保持只读。
- AMDA 定时路径自动处理固定工作簿中全部可见、日期命名的周度工作表，并将数据、图表、表格、API 回读、formal parity 和白板可见性校验作为写入门槛。
- AMDC 与 AMDA 通知统一发送到 `appmagic` 主题；AMDA 通知区分开始、完成和失败状态，并保留 AMDA 阶段耗时。
- 看板契约测试覆盖定时来源限制、自动收尾重试、AMDA 触发器和通知边界。

### 发布验证

- `npm run syntax` 通过。
- `npm run test:contract` 通过。
- `npm run test:feishu-order` 通过。
- 已完成定时 AMDC→AMDA 隔离端到端回归，数据、图表、表格、文档一致性和可见性校验全部通过。
- AMDA 完成通知、阶段耗时记录和正式文档只读边界通过契约验证。

## [1.1.7] - 2026-08-06

### 发布验证

- `am check` 的有效、异常和失效状态分支通过验证。
- ntfy 通知、账号配置暂存、私有仓库推送和远程一致性检查流程通过验证。
- 备份暂存区未包含缓存目录，PowerShell 语法检查通过。

## [1.1.6] - 2026-07-31

- Windows 每周三 09:30 任务改为无头调用本机看板的定时入口；看板未启动时由包装器无头启动后再提交任务。
- 看板成为采集、飞书同步和 ntfy 六阶段通知的唯一编排器；内部 PowerShell Worker 不再重复同步飞书或发送通知。

- 定时入口固定使用上周周一、七个品类和缓存采集；完成采集后自动同步飞书，并将同步状态写回相同历史记录。
- ntfy 阶段通知通过 `amdc` 主题发送，正文仅保留阶段说明和阶段耗时。

### 发布验证

- JavaScript、PowerShell 语法检查、看板契约测试和飞书工作表排序隔离测试通过。
- 无头定时包装器的账号检查、采集、周完成、总任务完成和飞书同步通知链路通过端到端验证。
- 定时运行历史落盘、飞书回读和重复内容跳过处理通过验证。

## [1.1.5] - 2026-07-30

### 变更

- 看板中的浏览器原生提示和确认框统一替换为页面同风格对话框；跨行内容左对齐并首行缩进两个字符。
- 历史记录左侧批量选择框首次点击选择所有“未同步”和“同步失败”记录，再次点击清空选择；未完成、旧版、同步中和排队同步的记录不会被选入。
- 飞书同步完成、失败、中止、事务回滚或重复内容跳过后，都会扫描整个目标电子表格，删除残留临时工作表，并将日期工作表按从新到旧排序。
- 账号 Profile 上限提升至 20 个；采集 Worker 上限与账号上限绑定，默认和最大值均为 20。
- 历史记录全选框在部分选中时使用蓝色原生中间态，不显示勾选。
- 看板顶部品牌区显示从 `package.json` 自动读取的当前版本号。

### 修复

- 修复 `am status` 将本地 Token 缓存状态误显示为黄灯的问题；现在按实时认证结果显示绿灯“正常”、黄灯“异常”和红灯“失效”。
- 修复设置面板直接展示账号邮箱的问题，改为脱敏显示，并同步更新 README 面板截图。
- 修复看板过早监听子进程 `exit` 事件，未等最终 JSON 输出完全读取就将“同步完成”误判为失败的问题；现改为在 `close` 后解析完整输出。
- 修复两条飞书同步并行进入整表排序时可能触发 `[Errno 36] Resource deadlock avoided` 的锁竞争问题；改为最多等待五分钟的非阻塞重试。
- 修复批量采集被中断后，历史结果目录存在但元数据或索引缺失时，历史列表将“采集周”显示为“--”的问题；会从可验证的批量状态映射恢复采集周和批次信息。
- 采集周未确认时，开始采集和全新采集会显示页面同风格引导并打开日期日历，不再因浏览器原生校验或按钮置灰而无法操作。

### 发布验证

- JavaScript、Python 语法检查、看板契约测试、飞书工作表排序隔离测试和 Git 差异检查通过。
- 已验证看板设置接口返回 20 个账号 Profile 和 20 个 Worker 上限；部分选中样式与飞书同步结果解析隔离测试通过。
- 浏览器实际验证历史批量选择首击选中未同步和同步失败记录、再次点击清空选择；设置面板邮箱脱敏显示正常。

## [1.1.2] - 2026-07-27

### 变更

- 区分“周任务完成”和“总任务完成”；单周完成只记录周任务完成，全部周完成后才触发总任务完成。
- 批量任务事件流和历史详情统一使用新的完成口径。
- 已补充契约测试，验证两类完成事件不会混用。
- 修复事件流轮询时总任务事件时间戳不断变化造成的闪烁；事件时间戳后增加具体采集周标识。
- 采集周标识改为直接显示日期，不再显示“周：”前缀。
- 任务运行期间禁用看板刷新，避免清空或覆盖运行中的进度视图。
- 重新采集已有周记录时取消任务，恢复取消前的历史记录，不再留下“已停止”记录。
- 国别数据未补齐时不再标记为周任务完成：进程以失败退出并保留缺失数量。
- 单周和多周采集均会在失败后最多自动重试三次；仍失败时标记失败并要求手工处理。
- 自动重试耗尽后通过浏览器原生弹窗提示失败和手工处理入口。
- 榜单确认阶段与应用数据采集阶段的自动重试次数独立计算，避免榜单阶段消耗应用数据阶段的重试额度。
- 批次结束时新增国别完成度兜底校验：即使所有周进程正常退出，只要仍缺国别数据，就只补采缺失的国别数据，并在耗尽后失败，不再显示 97% 的“总任务完成”。
- 进度文件改为原子写入，并在应用阶段初始化期间保留该周最后一次有效国别口径，修复批次进度短暂回退造成的闪烁。
- 任一采集周的缺失国别数据补采耗尽后立即弹出浏览器原生提示，无需等待整批任务结束。

## [1.0.0] - 2026-07-13

### 新增

- 新增本地实时看板，支持品类进度、焦点应用、飙升榜、市场分布、事件流和运行上下文。
- 新增深色/浅色主题切换，首次打开时采用系统主题作为初始值。
- 新增自定义周起点日历，支持文本输入、年份/月选择、滚轮切月和前后月份日期跳转。

- 新增输出目录快捷打开。

### 变更

- 采集周起点日强制使用周一；页面刷新或服务重启后默认恢复为上周周一。
- 默认榜单深度为 Top 100。
- 运行文件统一写入 `Cache/<YYYYMMDD>/`，Excel 输出统一写入 `output/AMDC-YYYYMMDD.xlsx`。
- 输出目录显示实际 XLSX 所在的 `output` 目录。
- 品类链接使用完整 AMDC 标签层级，例如 PDF 阅读器使用 `9,243756,244699`。
- Excel 导出内容统一单行、水平垂直居中，自动调整列宽并禁止换行。
- 全站字体统一优先使用微软雅黑。
- Windows 打开目录时隐藏命令行窗口。

### 修复

- 修复飙升榜应用名称列显示不完整和横向溢出问题。
- 修复浅色主题灰蒙、文字对比度不足及拖拽分隔线不清晰问题。
- 修复自定义日历切月、年份选择、月份选择和弹层关闭问题。
- 修复页面刷新后历史运行信息未清空的问题。
- 修复输出目录路径指向缓存目录的问题。

### 发布说明

- 运行环境要求 Node.js 18+、Python 3 和 `openpyxl`。
- Windows 默认看板地址为 `http://127.0.0.1:8787`。
